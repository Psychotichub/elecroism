ThreePhaseMCBSymbol
====================

Summary
-------
ThreePhaseMCBSymbol renders a multi-pole miniature circuit breaker (MCB/MCCB/MPCB) housing for 3P or 4P devices. It visualizes pole handles, terminal pockets, ratings, trip state and supports selection and interaction (toggle/double-click to operate unless tripped).

Location
--------
src/components/Components/ThreePhaseMCBSymbol.tsx

Props
-----
- component: CircuitComponent — used for state, type and properties like ratingAmps and tripCurve.
- nodeResult?: NodeResult — used to indicate energized visuals.
- onToggle: () => void — called on double-click (if not tripped) to toggle the breaker.
- onSelect: () => void — click handler.
- onDragEnd: (x: number, y: number) => void.
- showConnectionPoints: boolean — render connection point circles.
- selected: boolean — show selection outline.

Behavior
--------
- Supports 3-pole and 4-pole layouts based on component.type.
- Renders a housing, pole handles whose colors reflect on/off/tripped state. When `state === 'tripped'` a small flashing indicator is shown.
- Double-click triggers onToggle when not tripped.

Potential Issues / Things To Verify
----------------------------------
- The component flashes a tripped indicator using a setInterval that toggles every 500ms. This is cleared on unmount or state change — safe but verify there are no overlapping intervals for rapid state changes.
- The rendering computes pole positions from `poleXs` and derives overall body width; verify that connectionPoints generated by the model align with these positions.
- No code changes were made.

Testing Notes
-------------
- Verify toggling behavior via double-click when not tripped and ensure tripped state prevents toggling.
- Confirm visual appearance for 3P vs 4P devices, and that rating/tripCurve labels render when provided.

Implementation Notes / Required Modifications
-------------------------------------------
- Same note as MCBSymbol: flashing uses setInterval with a cleanup that clears it. Behaviour is correct; consider moving the interval id to a ref if you plan to add more complex lifecycle logic or if you expect effects to be mounted/unmounted multiple times in rapid succession.
